# Verified prefill and decode optimization on RTX 5090

This experiment asks whether reducing small-operation launch overhead improves the complete course-shaped Transformer workloads on an actual GPU. It extends the earlier shared-memory-only matrix model to full workloads and library-generated kernels. It does not claim that the original maximum-flow model predicts these runtimes.

M1/P1 has three layers, width 256, eight heads, a 1024-wide feed-forward layer, batch two, 64 prompt tokens and one continuation token. M2/D1 has two layers, width 128, four heads, a 512-wide feed-forward layer, batch one and eight sequential decode steps after 128 history tokens. Decode history construction is outside timing, as in the course reference. Prefill includes both prompt and continuation. Inputs are teacher-forced. All hidden outputs and all required new key/value outputs are checked.

Use one otherwise idle RTX 5090, GPU 0, for at most ten minutes. Do not install dependencies or modify other jobs. Existing torch-cu128 supplies PyTorch 2.11 and CUDA 12.8. FP32 arithmetic is retained; TF32 is disabled. The unchanged course float64 reference generates fixtures for seeds 7, 19, and 43. Require finite outputs and elementwise absolute error at most 0.001 plus 0.001 times the reference magnitude, matching the local course runner's tolerance. Correctness is necessary before performance admission; this is not a grading-server submission.

Three progressively expanded families are evaluated. The baseline uses explicit mean/variance normalization and the explicit tanh GELU expression. The second allows PyTorch fused layer normalization and tanh-approximate GELU. A finite optimizer enumerates the four combinations and minimizes a declared launch-count proxy (normalization: eight versus one; activation: eight versus one). These counts are a selection heuristic, not measured kernel counts or a fitted timing prediction. It chooses both fusions; real timing can reject this choice. The third permits CUDA Graph replay of the selected fused workload. This captures a fixed-shape inference call; inputs and weights remain resident and replayable. These extensions are clearly outside the original one-output/thread restriction, because library kernels own their mapping.

Each candidate is checked on three seeds before admission. Timing uses seed 7, ten warmups, and seven groups of ten calls. Each group records CUDA-event duration per call and synchronized host elapsed time per call. Report medians and the minimum/maximum across seven group averages; these ranges are descriptive variability, not confidence intervals. Rank by synchronized host time, which includes launch overhead and completion. Host-device copies, fixture construction, graph capture, and allocation of initial inputs are excluded from inference latency, but their actual elapsed optimization cost remains on the progress axis. Eager intermediate allocation is included. CUDA Graph replay reuses captured allocations; this is an explicit execution-mode difference.

The optimization clock starts in clock.json before this contract and implementation. Prior local simulation, server discovery, and the published baseline occurred before that clock and are not reconstructed. Candidate proposals, correctness, construction, capture, and timing all contribute elapsed time. Record each completed candidate's elapsed time and admit only verified improvements. Plot every candidate and a best-so-far step curve independently for prefill and decode, with milestone labels.

No numerical GPU roofline is asserted: there is no measured sustainable FP32 compute or memory calibration for these small, launch-sensitive complete workloads. A specification peak would not bound synchronized host throughput tightly enough to guide this comparison. The separate simulator chart can show its explicitly derived instruction-service ceiling, but that line must never be transferred to GPU charts.

Preserve local outputs, source hashes, configurations, complete timing samples, correctness errors and environment details. No push, course upload, or unrelated remote job termination is authorized by this experiment.
